# UzAssets — Каталог интеграционных API (Реестр услуг + Описание интерфейсов)

> **Технологическая инструкция** по интеграции 1С/ERP ↔ UzAssets.
> Структура документа соответствует **O‘zMSt 151:2024** «Информационная технология.
> Требования к интеграции и взаимодействию информационных систем» §6, который
> допускает объединение документов *«Описание процедуры системной интеграции»*,
> *«Реестр услуг»*, *«Соглашение об уровне услуг (SLA)»* и *«Описание интерфейса»*
> в один документ под наименованием **«Технологическая инструкция»**.
>
> Это **машиночитаемый справочник** для будущего извлечения точных данных из/в
> платформу. Полевые спецификации в JSON — рядом: `finmodel.endpoints.json`,
> `treasury.endpoints.json`, `spravochniki.endpoints.json`.

---

## 1. Область применения

Регламентирует обмен финансовыми, производственными и казначейскими данными между
учётными системами предприятий (1С/ERP) и платформой UzAssets для 22 предприятий,
находящихся под управлением/наблюдением UzAssets. Модель обмена — **PUSH** (источник
инициирует отправку). Все источники данных описаны в трёх первичных ТИ:

| # | Первичный документ | Базовый домен | Сервисов | Класс данных |
|---|---|---|---|---|
| 1 | `ТИ_UzAssets_FinModel_*` v3 | `https://api-uzassets.tenzorsoft.uz` | 16 | Финансы/производство (FinModel) |
| 2 | `TI_UzAssets_Treasury_*` v2.4 | `https://api.uz-assets.uz` | 29 | Казначейство (заявки/лимиты/платежи) |
| 3 | `ТИ_UzAssets_API_spravochniki` v3.6 | `https://api.uz-assets.uz` | 5 | Мастер-данные + AR/AP |

> Владелец интеграционного backend — **Tenzorsoft**. Технологический стек целевого
> API — Java/Spring (типы `Long`, `BigDecimal`, `List<DTO>`). Это **отдельная** система
> от Vue/FastAPI-стека настоящего репозитория; данный каталог — справочник для
> построения клиента/обмена, а не описание эндпоинтов этого репозитория.

## 3. Описание процедуры системной интеграции (O‘zMSt 151:2024 §6.4)

### 3.1. Рекомендуемый порядок загрузки (зависимости сервисов)
```
Departments → Products → FinModel Account List → (Limit Articles) →
  → Master-data готова → Operational/Financial PUSH:
      AR/AP Open Items, FinModel (working-capital, sales-revenue, …),
      Treasury (purchase-requests → budget → payments)
```

### 3.2. Общие конвенции обмена
| Параметр | Значение |
|---|---|
| Протокол | HTTPS, метод **POST** |
| Формат | `application/json; charset=utf-8` |
| Авторизация | `Authorization: Basic base64(login:password)` (креды — на организацию) |
| Конверт (envelope) | `{ organizationId, date?|month?, data[] }` *(искл.: accounting-entries — без `date/month`, дата внутри записи)* |
| Даты | `YYYY-MM-DD`; проводки — ISO‑8601 datetime (`2026-02-21T10:31:11.674Z`) |
| Суммы | `number` (decimal), точка-разделитель |
| Идемпотентность | стабильный ключ `external1cId`/`external1CId` (+`organizationId`) |
| Batch | 200–1000 записей; ретраи только на 429/5xx; backoff 1→2→4→8→16 с (≤5) |
| Метод интеграции (151:2024 Прил. А) | **Инкрементная** (подключение сервисов по одному в заданном порядке) |

### 3.3. Коды ответов и формат ошибки
`200/201` успех · `400` валидация · `401` auth · `403` доступ · `404` не найдено ·
`409` конфликт/дубль · `422` резолвинг внешних ID/бизнес-валидация · `413` payload ·
`415` media-type · `429` rate limit · `500` сервер.

```json
{ "errorCode": "LIMIT_ARTICLE_NOT_FOUND_BY_1C_ID",
  "message": "Limit article not found for external id=6100",
  "details": { "field": "article1cId", "value": "6100" } }
```
Batch-ответ (рекомендация): `{ "received":100, "created":80, "updated":20, "errors":[{"index":3,"field":"docDate","message":"Expected YYYY-MM-DD"}] }`

## 4. Реестр услуг / сервисов (O‘zMSt 151:2024 §6.5)

> Для каждого сервиса: путь, метод, назначение, периодичность, ключ идемпотентности,
> класс данных, статус реализации (из исходных Excel/ТИ). Реестр госсистем подлежит
> **пересмотру каждые 6 месяцев** и направлению в Мин. цифровых технологий РУз (151:2024 §6.5).

### 4.1. Мастер-данные и AR/AP (`/api/v1/basic/...`)
| Сервис | Метод | Endpoint | Периодичн. | Ключ идемпот. | Статус |
|---|---|---|---|---|---|
| Departments | POST | `/departments/create` | по событию | `organizationId+external1CId` | Частично |
| Products | POST | `/products` | по событию | `organizationId+productKod` | Сделано |
| Account List (план счетов) | POST | `/finmodel/integrations/account-list` | по событию | `organizationId+accountCode` | Сделано |
| AR/AP Open Items | POST | `/arap/open-items/create` | по событию/день | `external1CId` | — |

### 4.2. FinModel — финансы/производство (`/api/v1/basic/finmodel/integrations/{service}`)
| Сервис (service) | Период | Поле периода | Endpoint-suffix |
|---|---|---|---|
| Working Capital | Ежедневно | `date` | `working-capital` |
| Taxes | Ежемесячно | `date` (кон. мес.) | `taxes` |
| Sales Revenue | Ежедневно | `date` в записи | `sales-revenue` |
| Sales COGS | Ежедневно | `date` | `sales-cogs` |
| Production Costs | Ежемесячно | `month` | `production-costs` |
| Investment CAPEX | Ежемесячно | `date` (кон. мес.) | `investment-capex` |
| Expenses Salary | Ежемесячно | `date` (кон. мес.) | `expenses-salary` |
| Expenses Operating | Ежемесячно | `date` (кон. мес.) | `expenses-operating` |
| Entries (проводки) | Ежедневно | `date` в записи (ISO‑8601) | `entries` |
| Debt Loans | Ежемесячно | `date` (кон. мес.) | `debt-loans` |
| Costs Products | Ежемесячно | `date` (кон. мес.) | `costs-products` |
| Cash Flows | Ежедневно | `date` | `cash-flows` |
| Accounting Balance (ОСВ) | Ежемесячно | без `date` (M‑1) | `accounting-balance` |
| Accounting Entries Payroll | Мес./день | `date` в записи | `…/finmodel-accounting-entries-payroll/create-all` |

> Полевые спецификации (типы, обязательность, ограничения, примеры) — в
> **`finmodel.endpoints.json`**. Справочник единиц измерения (`measurementUnitCode`)
> для sales-revenue — в **`measurement-units.json`**.

### 4.3. Treasury — казначейство (`/api/v1/basic/treasury/...`), 29 сервисов
| Группа | Endpoint(ы) |
|---|---|
| Статьи лимитов | `POST /limit-articles/create` |
| Плановые/закупочные заявки | `POST /purchase-requests` (`kind=PLAN`/`PURCHASE`); `POST /purchase-requests/save-documents`; `POST /purchase-requests/{id}/send-to-contracting` |
| Согласование (approval-v2) | `POST /approval-v2/flows`; `…/flows/{flowId}/steps`; `…/requests/current/bulk`; `…/payments/current/bulk`; `…/tasks/{taskId}/approve`; `…/tasks/{taskId}/return` |
| Годовой бюджет | `POST /budget-baselines`; `…/{id}/submit`·`/approve`·`/activate` |
| Переносы лимитов | `POST /limit-transfers`; `…/{id}/submit`·`/apply`·`/cancel` |
| Маркет-исследование | `POST /purchase-requests/{prId}/market-researches`(+`/items`,`/{rid}/sources`,`/{rid}/complete`) |
| Тендеры | `POST /tenders` |
| Платежи | `POST /payments/requests`; `…/{id}/partial-payments`; `…/{id}/mark-paid` |

> Полевые спецификации + enum (`PurchaseRequestStatus`, `TenderStatus`,
> `PaymentRequestStatus`, `LimitTransferStatus`, …) — в **`treasury.endpoints.json`**.
> Шаги согласования/бюджета/переносов используют ЭЦП **`pkcs7`** (PKCS#7) —
> см. нормативные ссылки §2.2 (13888, 807/847, 9798‑3).

## 5. Соглашение об уровне услуг — SLA (O‘zMSt 151:2024 §6.7)

| Пункт | Значение (целевое, уточняется при заключении) |
|---|---|
| Объём услуг | Приём batch-пакетов по перечню §4 |
| Доступность | 24×7; окно обслуживания согласуется; цель ≥ 99.0% |
| Сроки данных | Ежедневные — до 02:00 D‑1; ежемесячные — до 5‑го числа M‑1 |
| Контроль доступа/ИБ | Basic Auth по организации, только HTTPS, allowlist по IP/VPN; §2.2 |
| Инциденты | Контакт через PM/Integration Lead; уведомление об инцидентах/жалобах |
| Критерии приёмки | Smoke (200/201), 401 на неверный auth, 400 на невалидные поля, идемпотентность без дублей, batch 200/1000, ретраи 429/5xx |
| Метрики мониторинга | req/min по endpoint+org, доля 4xx/5xx, p50/p95, created/updated |

## 6. Описание интерфейса (O‘zMSt 151:2024 §6.8)

Характеристики интерфейса для всех сервисов §4:

- **Системы интерфейса:** источник — учётная система предприятия (1С/ERP);
  приёмник — UzAssets backend (Tenzorsoft).
- **Стандарты и протоколы:** HTTPS/REST, JSON UTF‑8, Basic Auth, ЭЦП PKCS#7 (где
  требуется); соответствие §2.
- **Ответственные стороны:** предприятие (полнота/корректность/единицы/коды);
  UzAssets (приём/валидация/логирование/доступность); администратор интеграции (креды).
- **Передаваемые записи данных:** см. полевые JSON-спецификации (§4.2–4.3).
- **График работы интерфейса:** см. периодичность в Реестре услуг (§4) и SLA (§5).
- **Обработка ошибок:** коды и формат — §3.3; политика batch — fail-fast или
  partial с перечнем ошибок по индексам.

Машиночитаемое описание интерфейса (параметры запроса/ответа по каждому endpoint) —
в JSON-файлах этого каталога.
